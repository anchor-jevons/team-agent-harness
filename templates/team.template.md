# 团队协作

## 分工

每张 ticket 由人明确主要负责人。Agent 执行指定任务；本地 Owner/Status 不作为跨分支的抢票锁。

同一 feature 并行开发时先共享 spec 与拆票基线，各自维护对应 ticket。公共需求或领域定义变化在 MR 中说明对其他任务的影响。

## 接手

交接至少给出 ticket/主题和可获取的分支、提交或 MR。接手者同步对应版本，再读取任务、相关规则、领域资料和最近 Handoff，并核对当前代码及依赖。

仅保存到本机的未提交文件不算已共享。当前 worktree 中的任务、代码和日志一起提交。

## 记录

关键问答与确认及时写入 spec；术语和决策按 `domain.md` 维护。阶段记录由 `team-record-session` 保存，不能保证会话突然退出时完成收尾。

## 合并

代码和相关任务、决策、验证记录尽量同 MR review。除了文本冲突，还要检查相关需求、术语、ADR 与实现的语义一致性。

## 规则迭代

从真实任务提出可复用规则，经 MR review 后形成共享基线。技能版本与适配清单保存在 `.agents/skills/README.md`，更新后通过 Git 同步并重新加载相关指令。
