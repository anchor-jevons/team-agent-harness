# 领域文档约定

涉及领域术语或架构取舍时，从当前 worktree 根目录读取 `CONTEXT-MAP.md`，按当前任务选择相关领域。Map 的相对链接从 map 文件所在目录解析。

首次澄清领域词汇且尚无文档时，同时建立根 map 和 `project-name/CONTEXT.md`；只有映射关系，没有正文目标，不算完成初始化。没有领域建模需求时正常继续工作。

## CONTEXT

只记录当前有效的领域术语，定义保持简短。更新、合并和修订现行定义，历史留在 Git。需求问答进 spec，实现过程进 journal。

真实出现领域边界后再拆分词汇表并更新 map。不能以项目目录层数或开发时间代替领域边界。

## ADR

重要且有真实取舍的架构决策写入根 `docs/adr/`。文件名采用日期、唯一标识与主题，创建时检查未占用；引用完整相对路径。

草稿可以修订；已接受的实质决策变化使用新 ADR 并链接替代关系。分支里的状态词不代表 MR 已批准。合并前检查与目标基线及相关实现的语义一致性。
